# Rubric Score สำหรับอาจารย์ให้คะแนนนักศึกษา + นโยบาย Tie-Break
*(v3 — ปรับตามการยืนยันล่าสุด: เหลือ 2 เกณฑ์ น้ำหนักเท่ากัน, สเกล 1-100, ปรับ Tie-break chain)*

## หลักการออกแบบ

Rubric ยังคงเดินตามหลักเดิม: **หยาบพอที่จะกรอกง่ายและสม่ำเสมอ แต่ไม่ทิ้งข้อมูลละเอียดที่ใช้ตัดสิน Tie ได้** เพียงแต่ปรับ 2 จุดตามการตัดสินใจล่าสุด:

1. **ตัดเกณฑ์ Group Feasibility (D) ออก** เหลือ 2 เกณฑ์คือ Topic-Expertise Fit (A) และ Topic Clarity & Feasibility (B) น้ำหนักเท่ากัน 50/50
2. **ขยายสเกลจาก 1-5 เป็น 1-100** — เหตุผลที่ใช้ได้จริงในกรณีนี้ (ต่างจากระบบเก่า): คะแนนนี้ใช้เป็น **Ordinal input ภายในรายการของอาจารย์แต่ละคนเท่านั้น** ไม่เคยถูกนำไปรวม/เทียบข้ามอาจารย์เพื่อตัดสินสิทธิ์เหมือนระบบเก่า (ที่ Sum คะแนนจากหลายฝั่งมาเทียบกันจนเกิด Popularity Bias) ดังนั้นปัญหา Interpersonal Comparability ระหว่างอาจารย์ที่ "ให้คะแนนหลวม" กับ "ให้คะแนนเข้ม" จึงไม่กระทบผลลัพธ์ เพราะแต่ละอาจารย์ถูกใช้แค่เรียงลำดับกลุ่มของตัวเอง ไม่ถูกเทียบกับอาจารย์ท่านอื่น — สเกลกว้างขึ้นจึงช่วยลด Tie ได้จริงโดยไม่ดึงปัญหาเดิมกลับมา

โครงสร้างยังคงเป็น 2 ชั้นเหมือนเดิม:

- **ชั้นที่ 1 — Main Score (1-100)**: สิ่งที่อาจารย์กรอกจริงใน MS Forms ต่อกลุ่ม (ปัดเศษเป็นจำนวนเต็ม) ใช้เป็น Input หลักของ HRT Algorithm
- **ชั้นที่ 2 — Sub-criteria (ซ่อนอยู่เบื้องหลัง Main Score)**: ใช้คำนวณ Main Score และเก็บไว้เป็น Tie-breaker แบบละเอียด ระบบคำนวณให้อัตโนมัติจาก Checklist สั้นๆ

> **ข้อจำกัดสำคัญ: Anonymous Constraint** (คงหลักการเดิม)
> อาจารย์เห็นกลุ่มนักศึกษาแบบ Anonymous ไม่เห็นชื่อ/ประวัติ/ผลการเรียน เกณฑ์ทุกข้อจึงต้องประเมินได้จาก **หัวข้อที่เสนอ + รายละเอียดพอสังเขปที่กลุ่มเขียนมา** เท่านั้น

---

## ชั้นที่ 1: Rubric หลัก (1-100) — สิ่งที่อาจารย์กรอก

| ช่วงคะแนน | ระดับ | คำอธิบาย (Anchor) |
|---|---|---|
| **81-100** | ยอดเยี่ยม | หัวข้อสอดคล้องกับความเชี่ยวชาญของอาจารย์อย่างชัดเจน หัวข้อที่เสนอมีความเป็นไปได้และชัดเจนมาก อยากรับไว้เป็นอันดับต้นๆ |
| **61-80** | ดี | สอดคล้องกับความเชี่ยวชาญในระดับดี หัวข้อมีความเป็นไปได้ ต้องปรับแก้เล็กน้อย |
| **41-60** | พอใช้ | สอดคล้องบางส่วน ต้องปรับขอบเขตหัวข้อพอสมควร รับได้แต่ไม่ใช่กลุ่มที่โดดเด่น |
| **21-40** | ต้องปรับปรุงมาก | หัวข้อไม่ค่อยตรงกับความเชี่ยวชาญ ต้องปรับโครงสร้างหัวข้อใหม่มาก |
| **1-20** | ไม่เหมาะสม | ไม่สอดคล้องกับความเชี่ยวชาญเลย หรือมีข้อกังวลชัดเจนเรื่องความพร้อม |

> Anchor นี้ยังคงจำเป็นแม้สเกลจะกว้างขึ้น เพื่อช่วยให้อาจารย์แต่ละคน**สม่ำเสมอกับตัวเอง**เวลาให้คะแนนกลุ่มต่างๆ (Intra-rater consistency) — ไม่ต้องกังวลเรื่องเทียบกับอาจารย์ท่านอื่น เพราะ Algorithm ไม่ได้เอาไปเทียบข้ามคนอยู่แล้ว
>
> อาจารย์ให้คะแนนนี้ต่อ **1 กลุ่ม** ครบทุกกลุ่ม (Complete List เช่นเดิม)

---

## ชั้นที่ 2: Sub-Criteria (คำนวณ Main Score อัตโนมัติ + เก็บไว้ Tie-break)

ให้อาจารย์ตอบ Checklist สั้นๆ **2 หัวข้อ** (กรอกตัวเลข 1-100 ในแต่ละหัวข้อย่อย) ระบบจะเฉลี่ยให้เป็น Main Score อัตโนมัติ (ปัดเศษเป็นจำนวนเต็ม 1-100) ส่วนค่าเฉลี่ยแบบไม่ปัดเศษ (Decimal) เก็บไว้เป็น Tie-breaker

| หัวข้อย่อย | น้ำหนัก | คำถามที่อาจารย์เห็น |
|---|---|---|
| **A. Topic-Expertise Fit** | **50%** | หัวข้อที่กลุ่มนี้เสนอ ตรงกับความเชี่ยวชาญของท่านแค่ไหน? |
| **B. Topic Clarity & Feasibility** | **50%** | หัวข้อมีความชัดเจนและความเป็นไปได้ในการทำจริงแค่ไหน? |

**สูตรคำนวณ:**

```
Sub-score รวม (ไม่ปัดเศษ) = 0.5A + 0.5B
Main Score (ที่ใช้จริงใน HRT) = round(Sub-score รวม)
```

**เหตุผลของน้ำหนักเท่ากัน:** เมื่อตัด Group Feasibility ออกแล้ว เหลือ 2 เกณฑ์ที่ถือว่ามีความสำคัญเทียบเท่ากันในการชี้วัด "คุณภาพของการเป็นที่ปรึกษา" — ความเชี่ยวชาญตรงหัวข้อ (A) กับความชัดเจน/ความเป็นไปได้ของหัวข้อ (B) จึงให้น้ำหนักเท่ากัน 50/50 ไม่มีเกณฑ์ไหนสำคัญกว่ากัน

---

## ชั้นที่ 3: นโยบาย Tie-Break (สำหรับ Boundary Tie ใน HRT)

Boundary Tie เกิดเมื่ออาจารย์ให้ Main Score เท่ากันหลายกลุ่ม ณ ตำแหน่งที่ Quota เต็มพอดี ให้ตัดสินตามลำดับนี้ (หยุดที่ชั้นแรกที่ตัดสินได้):

### ชั้น 1 — Sub-score แบบ Decimal (ไม่ปัดเศษ)
เทียบ Sub-score รวมที่ไม่ปัดเศษของกลุ่มที่ Tie กัน กลุ่มที่ Sub-score สูงกว่าชนะ
> เช่น กลุ่ม G1 ได้ Main Score 75 จาก Sub-score 75.4 และกลุ่ม G2 ได้ Main Score 75 จาก Sub-score 74.6 → G1 ชนะ

### ชั้น 2 — อันดับที่นักศึกษากลุ่มนั้น Rank อาจารย์ท่านนี้ไว้
ถ้า Sub-score เท่ากันเป๊ะ (พบได้น้อยลงมากเมื่อสเกลกว้างขึ้น) ให้ดูว่ากลุ่มไหน Rank อาจารย์ท่านนี้ไว้อันดับสูงกว่าในรายการของฝั่งนักศึกษาเอง (สะท้อนว่า Match นี้ "อยากได้" มากกว่าจริง) — ยังคง Fair เพราะอิงจาก Preference ที่มีอยู่แล้วในระบบ ไม่ใช่เกณฑ์ใหม่ที่ยัดเข้ามา

### ชั้น 3 — Seeded Random (ทางเลือกสุดท้ายเท่านั้น)
ถ้ายัง Tie อยู่จริงๆ (ทั้ง Main Score, Sub-score, และอันดับที่นักศึกษาให้ เท่ากันหมด) ให้สุ่มด้วย Seed ที่กำหนดไว้ล่วงหน้าและ **บันทึก Seed ไว้ใน Log ของระบบ** เพื่อให้ตรวจสอบย้อนหลังได้เสมอว่าทำไมกลุ่มนี้ถึงได้/ไม่ได้ — ห้ามสุ่มแบบไม่มี Seed เก็บไว้ เพราะจะกลับไปมีปัญหาแบบระบบเก่า

> เมื่อสเกลกว้างขึ้นจาก 1-5 เป็น 1-100 การถึงชั้น 3 (Random) ควรเกิดขึ้นน้อยลงมากในทางปฏิบัติ เพราะโอกาสที่ Sub-score จะเท่ากันเป๊ะข้ามหลายกลุ่มลดลงตามธรรมชาติ — ยังคงเก็บ Random ไว้เป็น Safety Net สุดท้ายเผื่อกรณีบังเอิญเท่ากันจริง

---

## สรุปการไหลของข้อมูล

```
อาจารย์กรอก Checklist 2 ข้อ (A, B) ต่อกลุ่ม (สเกล 1-100)
        ↓
ระบบคำนวณ Sub-score (decimal) + Main Score (1-100, ปัดเศษ)
        ↓
Main Score (1-100) → เข้า HRT Algorithm เป็น Preference หลัก
        ↓
ถ้าเกิด Boundary Tie ตอนตัด Quota
        ↓
ใช้ Sub-score decimal → Rank ที่นักศึกษาให้อาจารย์ท่านนี้ → Seeded Random (ตามลำดับ)
```

วิธีนี้ทำให้ Main Score ที่อาจารย์เห็นและกรอกยังคงมี Anchor ชัดเจนเหมือนเดิม (ลด Bias จากการตีความคะแนนไม่ตรงกัน) แต่สเกลที่กว้างขึ้นช่วยลดโอกาสเกิด Tie ได้มากโดยไม่กระทบความยุติธรรม เพราะคะแนนไม่เคยถูกนำไปเทียบข้ามอาจารย์เพื่อตัดสินสิทธิ์เหมือนระบบเก่า — ส่วน Tie-break policy ที่เหลือ 3 ชั้น (Sub-score → Rank ฝั่งนักศึกษา → Seeded Random) ยังคงอธิบายได้และตรวจสอบย้อนหลังได้ครบทุกขั้นตอน
