# Prompt สำหรับ Antigravity IDE — ปรับตาราง Student-Proposing vs Professor-Proposing

> คัดลอกเนื้อหาด้านล่างวางใน Antigravity IDE ได้เลย แนบ Screenshot หน้าตารางปัจจุบันไปด้วย เพื่อให้ AI เห็นโครงสร้าง Component เดิมก่อนแก้

---

## บทบาทของคุณ

คุณกำลังแก้ไขหน้า/Component ตารางเปรียบเทียบผลลัพธ์ **Student-Proposing vs Professor-Proposing** ที่มีอยู่แล้วในระบบ (ไม่ใช่สร้างใหม่) โครงสร้างปัจจุบัน:

- แถวสรุปด้านบน: จุดสี Legend ของ 2 โหมด + ข้อความเตือน "N กลุ่มได้ผลต่างกันระหว่างสองโหมด"
- ตาราง 1 แถวต่อ 1 กลุ่ม แบ่งเป็น 2 บล็อกคอลัมน์คู่กัน (ซ้าย = Student-Proposing, ขวา = Professor-Proposing) แต่ละบล็อกมี: อาจารย์, อันดับ, Score
- คอลัมน์สุดท้าย: Indicator "ต่าง" / "—" บอกว่าแถวนั้นผลลัพธ์เหมือนหรือต่างกันระหว่างสองโหมด

**เป้าหมาย**: แก้ไข 3 จุดตามนี้ — (1) ลบคอลัมน์ Score ทั้งสองฝั่งออก (2) เพิ่มปุ่ม Toggle กรองเฉพาะกลุ่มที่ต่างกัน (3) เพิ่มปุ่ม Toggle เรียงตาม Impact

---

## 1. ลบคอลัมน์ "Score" ออกทั้งสองฝั่ง

**เหตุผล (ใส่ไว้เป็น Comment ในโค้ดด้วยเพื่อกันคนมาเพิ่มกลับ)**: Score เป็นคะแนนที่อาจารย์แต่ละคนให้ตาม Rubric ของตัวเอง ใช้เป็น Ordinal Preference ภายในรายการของอาจารย์คนนั้นเท่านั้น **ไม่ได้ถูกออกแบบให้เทียบข้ามอาจารย์คนละคนได้** การวางคอลัมน์ Score จากอาจารย์ 2 คนต่างกันไว้ข้างกันทำให้แอดมินเข้าใจผิดว่าเทียบกันได้โดยตรง (เช่น "89 ดีกว่า 38") ทั้งที่ไม่ใช่

- ลบ Column Header "Score" และเซลล์ข้อมูลทั้งสองฝั่งออกจาก Table
- ปรับความกว้างคอลัมน์ที่เหลือ (อาจารย์, อันดับ) ให้ขยายเติมพื้นที่ที่ว่างลง
- **คง** คอลัมน์ "อันดับ" ไว้ทั้งสองฝั่งเหมือนเดิม (เป็นข้อมูลที่เทียบข้ามได้จริง เพราะมาจาก Ranking List เดียวกันของกลุ่มนั้น มาตรฐานเดียวกันทุกกลุ่ม)
- **คง** คอลัมน์สุดท้าย "ต่าง / —" ไว้ตามเดิมทุกประการ (Binary Indicator บอกแค่ต่างหรือไม่ต่าง ไม่ต้องเพิ่มทิศทางหรือขนาดผลต่างในคอลัมน์นี้)

---

## 2. เพิ่ม Toggle: "แสดงเฉพาะกลุ่มที่ต่างกัน"

- วางเป็น Checkbox หรือ Switch ไว้แถวเดียวกับ Legend ด้านบนตาราง (ฝั่งขวา)
- เมื่อเปิด: กรองให้ตารางแสดงเฉพาะแถวที่คอลัมน์สุดท้ายเป็น "ต่าง" เท่านั้น (ซ่อนแถวที่เป็น "—")
- เมื่อปิด (Default): แสดงทุกแถวเหมือนเดิม
- **คอลัมน์ # (ลำดับแถว) ต้องนับใหม่ตามที่แสดงจริงบนหน้าจอ** (1, 2, 3, ... ตามจำนวนแถวที่กรองแล้ว) ไม่ใช่เลขเดิมจาก List เต็ม — คอลัมน์ "กลุ่ม" (รหัส G-code) ทำหน้าที่อ้างอิงตัวตนของแถวอยู่แล้ว จึงไม่มีปัญหาเรื่องอ้างอิงข้อมูลผิดกลุ่ม
- **ข้อความสรุปด้านบน** ("N กลุ่มได้ผลต่างกันระหว่างสองโหมด") **ต้องคงค่าจากข้อมูลเต็มเสมอ ไม่เปลี่ยนตาม Filter ที่เปิดอยู่** เพื่อไม่ให้แอดมินหลุดบริบทภาพรวม

---

## 3. เพิ่ม Toggle: "เรียงตาม Impact"

- วางคู่กับ Toggle ข้อ 2
- **ต้องมีการคำนวณ Field ที่ใช้เป็น Sort Key เก็บไว้เสมอ** แม้จะไม่แสดงในตาราง: `impact = abs(rank_professor_proposing - rank_student_proposing)` ต่อกลุ่ม — ถ้ายังไม่มี Field นี้ในข้อมูลที่ส่งมาจาก Backend ให้เพิ่มการคำนวณที่ Frontend ได้ (ไม่จำเป็นต้องแก้ Backend ถ้าข้อมูล Rank ทั้งสองฝั่งมีอยู่แล้ว)
- เมื่อเปิด: เรียงตาราง (หรือชุดข้อมูลหลังกรองจาก Toggle ข้อ 2 ถ้าเปิดอยู่ด้วย) จาก Impact มากไปน้อย
- เมื่อปิด (Default): เรียงตามลำดับกลุ่ม G1 → G15 เหมือนเดิม (Behavior เดิมของตาราง)
- แถวที่ Impact = 0 (ผลเหมือนกันทั้งสองโหมด) ให้อยู่ท้ายสุดเสมอเมื่อเปิด Sort by Impact

---

## เงื่อนไขการทำงานร่วมกันของ 2 Toggle (สำคัญ)

Toggle ทั้งสองต้องใช้งานพร้อมกันได้โดยไม่ขัดกัน ลำดับการประมวลผลต้องเป็น:

```
ข้อมูลเต็ม (15 กลุ่ม)
   → กรองตาม Toggle "แสดงเฉพาะกลุ่มที่ต่างกัน" (ถ้าเปิด)
   → เรียงตาม Toggle "เรียงตาม Impact" (ถ้าเปิด) บนชุดข้อมูลที่กรองแล้ว
   → แสดงผล พร้อมเลข # นับใหม่
```

ทดสอบทั้ง 4 Combination ก่อนส่งงาน: (ปิด,ปิด) / (เปิด,ปิด) / (ปิด,เปิด) / (เปิด,เปิด)

---

## สิ่งที่ไม่ต้องแก้

- Layout 2 บล็อกคอลัมน์ซ้าย-ขวา (Student-Proposing / Professor-Proposing) คงไว้เหมือนเดิม
- สีของ Legend และหัวตารางแต่ละฝั่งคงไว้เหมือนเดิม
- คอลัมน์ "ต่าง / —" คงเป็น Binary Indicator เหมือนเดิม ไม่ต้องเพิ่มทิศทางหรือแถบผลต่าง
