# Prompt สำหรับ Antigravity IDE — ปรับปรุงหน้า Dashboard (Admin)

> คัดลอกเนื้อหาด้านล่างวางใน Antigravity IDE ได้เลย แนบ Screenshot หน้า Dashboard ปัจจุบันไปด้วย (ถ้ามี) เพื่อให้ AI เห็นโครงสร้าง Component เดิมก่อนแก้

---

## บทบาทของคุณ

คุณกำลังแก้ไขหน้า **Dashboard** ที่มีอยู่แล้วในระบบ Professor-Student Matching System (ไม่ใช่สร้างใหม่) หน้านี้เป็นหน้าแรกที่แอดมินเห็นหลัง Login ปัจจุบันมี Layout ดังนี้:

- แถวการ์ดสถิติ 4 ใบ: กลุ่มนักศึกษา, อาจารย์, Quota รวม, จับคู่ล่าสุด
- การ์ด Pipeline (ซ้าย) แสดง Checklist 5 ขั้นตอนพร้อมเครื่องหมายถูก
- การ์ด "การดำเนินการ" (ขวา) เป็นปุ่มลัด 4 ปุ่ม
- การ์ด "ข้อมูลล่าสุด" และ "การรันล่าสุด" ด้านล่างขวา

**เป้าหมาย**: ปรับ Layout เดิมให้ตอบโจทย์การใช้งานจริงมากขึ้น โดยเน้นให้แอดมิน**เห็นปัญหาได้ทันที**และ**รู้ว่าต้องทำอะไรต่อ** ไม่ใช่แค่แสดงสถานะว่าปกติ

## รายการที่ต้องแก้ไข (เรียงตามความสำคัญ)

### 1. เพิ่ม Alert Banner ด้านบนสุด (Conditional)

เพิ่ม Component ใหม่เหนือแถวการ์ดสถิติ **แสดงเฉพาะเมื่อมีเงื่อนไขผิดปกติ** (ไม่แสดงถ้าทุกอย่างปกติ):

- เงื่อนไขที่ต้อง Trigger Banner:
  - ข้อมูล (Group_Info / Professor_Info / Student_Rankings / Professor_Scores) ถูกแก้ไข/อัปโหลดใหม่ **หลัง**เวลาที่รัน Matching ครั้งล่าสุด → ข้อความ: "ข้อมูลมีการอัปเดตหลังรันล่าสุด — [ชื่อไฟล์/ชีตที่เปลี่ยน] แก้ไขเมื่อ [เวลา] แต่รันล่าสุดคือ [เวลา] ควรรันใหม่" พร้อมปุ่ม "รันใหม่" ที่ลิงก์ไปหน้า Run Matching ทันที
  - ผลรวม Quota ของอาจารย์ < จำนวนกลุ่มนักศึกษา → ข้อความเตือนสีแดง (ระดับ Error ไม่ใช่แค่ Warning) พร้อมปุ่มลิงก์ไปหน้าจัดการข้อมูลอาจารย์
  - การรันล่าสุดมีกลุ่ม Unmatched > 0 → ข้อความเตือนพร้อมจำนวนกลุ่มที่ยังไม่ได้จับคู่ และลิงก์ไปดูรายละเอียดที่หน้าผลลัพธ์
- ใช้สี Warning (เหลือง/ส้ม) สำหรับกรณีทั่วไป และสี Danger (แดง) เฉพาะกรณี Quota ไม่พอ (บล็อกการทำงานจริง)
- ถ้ามีหลายเงื่อนไขพร้อมกัน ให้แสดงได้มากกว่า 1 Banner เรียงตามลำดับความรุนแรง (Danger ก่อน Warning)

### 2. ปรับการ์ดสถิติจาก 4 ใบ ให้เหลือแค่เนื้อหาที่จำเป็น

- รวม "อาจารย์" กับ "Quota รวม" เป็นการ์ดเดียว: หัวข้อ "อาจารย์ / Quota รวม" ค่า "10 ท่าน • 16" (ตัวเลข Quota เป็นตัวเล็กกว่าต่อท้าย)
- การ์ด "จับคู่ล่าสุด" เปลี่ยนจากตัวเลขเดี่ยว (`15 กลุ่ม`) เป็น **อัตราส่วน** (`15 / 15`) โดยใช้จำนวนกลุ่มทั้งหมดเป็นตัวหาร
  - ถ้า Matched = Total → พื้นหลังการ์ดเป็นสี Success (เขียวอ่อน), ตัวเลขสี Success
  - ถ้า Matched < Total → พื้นหลังการ์ดเป็นสี Warning/Danger ตามสัดส่วนที่ขาด, ตัวเลขสีเดียวกัน
- เพิ่มการ์ดใหม่ **"โหมดล่าสุด"** แสดงว่าการรันล่าสุดใช้โหมดไหน (`Student-Proposing` / `Professor-Proposing` / `Student + Professor`) พร้อมลิงก์ย่อย "ดูเปรียบเทียบ →" ที่ลิงก์ไปหน้าผลลัพธ์แบบ Comparison (เฉพาะกรณีรันแบบ Both)

### 3. ปรับ Pipeline ให้ระบุปัญหาที่จุดนั้นเจาะจง ไม่ใช่แค่ % รวม

สำหรับแต่ละขั้นตอนใน Pipeline (กลุ่มนักศึกษา, อาจารย์, Student Rankings, Professor Scores, Matching Algorithm):

- ถ้าขั้นตอนนั้นยังไม่ครบ 100%: เปลี่ยนไอคอนจากเครื่องหมายถูกสีเขียว เป็นไอคอนเตือนสีเหลือง/ส้ม และข้อความบรรทัดที่สองต้องระบุ**ว่าใครยังขาด** ไม่ใช่แค่บอก % เช่น "93% ให้คะแนนแล้ว — เหลืออาจารย์ [รายชื่อ Anonymous Code ที่ยังไม่ครบ]"
- เพิ่มปุ่ม/ลิงก์ "ติดตาม" ท้ายบรรทัดของขั้นตอนที่ยังไม่ครบ ลิงก์ไปหน้า Data Management พร้อม Filter ไปที่รายการที่ขาดโดยตรง (ถ้าทำได้ในเวอร์ชันนี้ ถ้าไม่ทัน ให้ลิงก์ไปหน้า Data Management เฉยๆ ก่อนได้)
- ขั้นตอนที่ครบ 100% แล้วยังคงแสดงเครื่องหมายถูกสีเขียวเหมือนเดิม ไม่ต้องเปลี่ยน

### 4. เพิ่มข้อมูลใน "การรันล่าสุด"

การ์ดนี้ต้องมีข้อมูลเพิ่มจากเดิม (ที่มีแค่ Status + Timestamp):

- **Seed** ที่ใช้ในการรันนั้น (ตัวเลข)
- **โหมด** ที่รัน (Student / Professor / Both)

### 5. เพิ่มการ์ดใหม่: "ประวัติการรัน 3 ครั้งล่าสุด"

วางใต้การ์ด "การรันล่าสุด" ในคอลัมน์ขวา แสดงเป็นรายการสั้นๆ (ไม่ใช่ตาราง เพราะพื้นที่แคบ) ต่อแถวประกอบด้วย:

- เวลาที่รัน (แบบย่อ) + โหมดที่ใช้
- ผลลัพธ์ Matched/Total (สีเขียวถ้าครบ, สีเหลือง/แดงถ้าไม่ครบ)
- แต่ละแถวกดแล้วลิงก์ไปหน้า History พร้อมเปิดรายละเอียดของรอบนั้นโดยตรง (Deep link ถ้าทำได้)

## Data/Backend ที่ต้องรองรับเพิ่ม (ถ้ายังไม่มี)

ให้ตรวจสอบว่า Backend มี Endpoint/Field รองรับสิ่งเหล่านี้หรือยัง ถ้ายังไม่มีให้เพิ่ม:

1. Timestamp การอัปโหลด/แก้ไขล่าสุดของแต่ละไฟล์/ชีตข้อมูล (Group_Info, Professor_Info, Student_Rankings, Professor_Scores) แยกจากกัน เพื่อใช้เทียบกับเวลารัน Matching ล่าสุด
2. รายชื่อ Anonymous Code ของอาจารย์/กลุ่มที่ยังกรอกข้อมูลไม่ครบ (ไม่ใช่แค่ % — ต้อง Query รายชื่อจริงมาแสดงได้)
3. Field `seed` และ `mode` (`student` / `professor` / `both`) ต้องถูกบันทึกไว้ในทุก Run ที่ผ่านมา (ตาม Schema การรันที่ออกแบบไว้ก่อนหน้านี้ ควรมีอยู่แล้วบางส่วน — ตรวจสอบให้ครบ)
4. Endpoint ที่คืนค่า 3 Run ล่าสุด (เรียงจากใหม่ไปเก่า) พร้อม Timestamp, Mode, Matched/Total

## หมายเหตุสำหรับการออกแบบ UI

- ใช้ชุดสี Success (เขียว) / Warning (เหลือง-ส้ม) / Danger (แดง) ให้สอดคล้องกับความรุนแรงของสถานะ ไม่ใช้สีตามใจชอบ
- Alert Banner ต้องไม่ทำให้ Layout กระโดด (Layout Shift) เวลาไม่มี Banner แสดง — ให้ Reserve พื้นที่หรือ Animate เข้า-ออกอย่างนุ่มนวล
- ทุกจุดที่เพิ่ม "ลิงก์ติดตาม/ดูเพิ่มเติม" ต้องเป็น Deep Link ที่พาไปหน้าที่เกี่ยวข้องโดยตรง ไม่ใช่แค่ไปหน้าแรกของ Section นั้นเฉยๆ

โปรดเริ่มจากการแก้ Component/State ของ Dashboard Page ก่อน แล้วค่อยไล่เพิ่ม Backend Endpoint ที่ยังขาด ให้แจ้งด้วยว่ามีจุดไหนที่ต้อง Migrate Database Schema เพิ่มหรือไม่
